# One Verse 구현 분석 요약

> 기준: 현재 `main` 코드베이스. 이 문서는 구현 사실을 기록하며, 제품 의도에 대한 내용은 `[추론]`으로 표기한다.

## 분석한 영역

- Route/Page: `/`, `/home`, `/read`, `/memo`, `/friends`, `/friend/[id]`, `/mypage`, `/verse/[date]`, `/settings`, `/auth/callback`
- 앱 셸/탐색: `MainLayout`, viewport 고정 하단 4탭 네비게이션, 페이지별 헤더와 내부 스크롤 컨테이너
- 인증/프로필: Supabase Auth, Kakao 로그인 진입, 닉네임 온보딩 모달
- 읽기: 365일 일정, Day 선택 시트, 4개 트랙, One Verse 초안, Mark 후보, 완료 확인/취소/재선택 모달
- 마음새김: 음성 인식/쓰기 기반 훈련 모달과 성공·실패 결과 모달
- 사회 기능: 친구 검색/요청/응답, 친구 발자국, 좋아요
- 기록: 발자국 작성·수정, 날짜별 One Verse 상세, 공유
- 데이터: `lib/storage.ts`의 읽기 설정/기록/One Verse/Mark 후보, `lib/social.ts`의 친구·좋아요, Supabase 클라이언트

## 핵심 User Journey

1. Kakao 로그인 후 닉네임 설정, 홈에서 읽기 시작
2. 오늘 허용된 Day의 4트랙을 읽고 One Verse 및 Mark를 선택한 뒤 읽기 완료
3. 완료한 One Verse로 마음새김(음성 또는 쓰기)을 수행
4. 발자국을 작성하거나 과거 날짜의 One Verse/발자국을 조회·공유
5. 친구를 찾고 요청을 처리하며 친구의 발자국에 좋아요

## 구조적 특징

- 읽기 완료 기록과 One Verse 초안은 별도로 복원된다. 완료 전에도 One Verse가 유지되도록 의도된 구현이다.
- Mark는 Day별 후보 목록으로 별도 저장되며, One Verse와 독립적으로 토글된다.
- 하단 네비게이션은 viewport 기준 fixed overlay이며 본문은 `pb-16`으로 이를 피한다.
- `/read`, 친구 상세, 친구, 마이페이지는 페이지 내부에서 헤더와 본문 스크롤을 분리한다.
- iOS PWA를 고려해 각 고정 헤더에만 top safe-area padding을 적용한다.

## UX 구조 이슈/관찰

- `/read`의 `handleSetDay`는 `window.scrollTo`를 호출하지만 실제 성경 본문은 `#bible-content-scroll`을 사용한다. Day 전환 때 본문 스크롤 초기화가 보장되는지는 추가 실기기 확인이 필요하다.
- 읽기 화면은 인증되지 않은 경우 자체 로그인 CTA를 제공하지만, 홈 등 다른 화면의 비인증 정책은 화면별로 다르다.
- 일부 로딩/오류 상태는 구현되어 있으나, 홈 데이터 로딩 실패의 사용자 메시지는 명시적으로 확인되지 않았다.
- `memory`, `memo` 등 내부 legacy naming과 사용자 용어인 마음새김/발자국이 공존한다.
- iPhone PWA 하단/상단 safe-area와 키보드 상태는 CSS 구조로 대응하나, 자동화 환경에서 iOS standalone 실기기 검증은 수행되지 않았다.

## 불확실한 부분

- Mark의 장기적 목적은 코드에 명시되지 않았다. `[추론]` 나중에 다시 볼 구절 후보를 보관하는 기능으로 보인다.
- 친구 요청/좋아요의 알림 전달 범위와 실시간성은 `friend_requests_updated` 브라우저 이벤트 외에는 코드만으로 확정할 수 없다.
- 음성 마음새김의 브라우저 권한 거부·STT 지원 불가 상태의 전체 UX는 hook과 브라우저 환경에 의존한다.
