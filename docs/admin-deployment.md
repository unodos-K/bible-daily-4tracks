# 관리자 코드 배포 및 확인

배포 경로: `unodos-K/bible-daily-4tracks`의 `main` push → Vercel Git 연동
Production (`bible-daily-4tracks.vercel.app`). DB 적용은 완료되어 재실행하지 않는다.

## 이번 UI 보완

- 관리자 화면에서 공통 레이아웃과 Day·아멘·알림·친구 목록의 중첩 세로
  스크롤을 제거하고 문서 스크롤을 사용한다. 다른 화면의 스크롤 정책은 유지한다.
- 내부 `min-height:100dvh`와 과도한 하단 여백을 제거한다.
  상하 safe area와 기존 하단 네비게이션 여백을 유지한다.
- 검색어 입력마다 요약을 새로 요청하던 effect 의존성을 정리한다.
- 알림 날짜 필터를 API가 받는 YYYY-MM-DD 형식으로 전달한다.
- 계정 변경 시 관리자 컴포넌트를 해제하여 조회 상태를 비운다.
- 관리자 페이지·API는 PWA NetworkOnly 경로로 처리한다.

## 배포 후 실제 로그인 확인 순서

1. 비로그인 `/admin`은 `/`로 이동, 관리자 API 5종은 401인지 확인.
2. 일반 계정으로 `/admin` 접근 차단, `/api/admin/summary` 403 확인.
3. 관리자 계정으로 요약 → 사용자 검색/페이지 이동 → 사용자 상세 →
   Day 선택 → 알림 조건 조회 → 데이터 점검 순서로 확인.
4. Network 응답에 개인 묵상·기도 원문이 없는지 확인.
5. 모바일에서 긴 상세 목록 위·중간·끝 스크롤, 키보드 열기/닫기, 화면 회전,
   하단 네비게이션 이동 후 복귀 확인.
6. 로그아웃·일반 계정 전환 후 관리자 데이터가 남지 않는지 확인.
7. 홈·말씀뷰어·친구·마이페이지 기본 이용 확인.

실제 로그인 세션을 사용할 수 없는 환경에서는 위 인증 사용자 시나리오를
완료로 간주하지 않는다. DB claim 모의 테스트는 HTTP 테스트를 대체하지 않는다.

상세 근거는 `admin-production-migration-audit.md`에 기록되어 있다.
