# 관리자 읽기 기록 보정

## 적용 상태

신규 마이그레이션 `20260919200000_admin_record_corrections.sql`은 작성 및
격리 SQL 테스트 완료 상태다. 이번 구현 중 운영 DB에는 적용하지 않았다.
이 파일은 이미 적용한 관리자 조회 마이그레이션 이후의 **새로운 쓰기 권한**을
추가하므로 기존 조회 기능 운영 적용 기록과 구분한다.
운영 적용 전 dry-run에서 대상과 차이를 확인하고, DB 적용 후 코드를 배포한다.
이전 8개 마이그레이션을 재실행하거나 이력을 repair하지 않는다.

## 동작과 날짜 정책

- `admin_complete_one_verse_record`: 최종 One Verse가 있고 completed_at이 NULL인
  기록만 완료. 입력 시각이 없으면 DB now() 사용. read_date는 보존.
- `admin_update_reading_record_date`: 지정 user_id / day_index의 날짜만 수정.
  완료 기록에서 시각을 비우는 완료 취소는 지원하지 않는다.
- 미완료이고 One Verse가 없는 기록도 read_date는 수정 가능하나 완료시각은 추가 불가.
- 모든 입력/표시는 Asia/Seoul 기준. 서버가 +09:00을 명시하여 UTC ISO로 변환.
  DB는 timestamptz로 저장. 브라우저 현지 시간대에 의존하지 않는다.
- 미래 read_date/완료시각, 통독 시작일 이전 값, 읽은 날짜 이전의 완료일은 거부.
  시작일 데이터가 없으면 추정하지 않고 오류 반환.
- 같은 날짜의 여러 Day를 허용한다. 기존 PK는 (user_id, day_index)이고
  getRecordsForReadDate()도 여러 Day를 지원한다. Day는 계획 인덱스이므로
  시작일 + Day - 1로 날짜를 강제하지 않는다. 과거 Day를 일찍/늦게 읽는 기존
  흐름을 유지하고 스케줄/현재 Day/다른 Day는 재계산하지 않는다.
- DB 기본 스키마보다 관리자 날짜 입력 정책이 엄격하다. 과거 이상 날짜는
  자동 변경하지 않는다. 해당 기록 편집 시 관리자가 유효한 날짜를 선택해야 한다.
- 현재 reading_records에는 created_at이 없으므로 다른 시각으로 대체하지 않는다.
  memorizedAt, 발자국, One Verse JSON, 아멘, 친구, 알림 행은 수정하지 않는다.

## 권한과 원자성

API는 getUser()로 인증 후 중앙 관리자 판정을 사용하고 동일 출처 JSON만 받는다.
외부 RPC 2개와 비공개 구현 함수 모두 admin_require_access()를 호출한다.
SECURITY DEFINER search_path는 빈 값이며 객체는 public/auth로 한정한다.
비공개 구현 함수의 PUBLIC/anon/authenticated 실행을 금지한다.
일반 사용자 테이블 RLS/ACL은 수정하지 않는다.

행 잠금과 기대한 기존 날짜 비교로 덮어쓰기 충돌을 409로 처리한다.
request_id에 대한 트랜잭션 advisory lock과 UNIQUE로 동일 요청 재시도 시
기존 결과를 반환한다. 같은 request_id의 다른 요청은 거부한다.
감사 INSERT와 기록 UPDATE는 같은 RPC 트랜잭션이며 둘 중 하나가 실패하면
둘 다 롤백된다. 실패/무변경에는 성공 감사 행을 남기지 않는다.

## 감사 및 알림

admin_audit_logs는 관리자/대상 UUID, Day, 작업, 날짜 필드 전후 값, 요청 ID,
요청 날짜 값, 트랜잭션 ID, 실행시각만 보관한다. 개인 본문은 저장하지 않는다.
일반 사용자 SELECT는 RLS로 0행, INSERT/UPDATE/DELETE 권한은 없다.
관리자만 SELECT 가능하다. 삭제 연쇄로 감사 기록이 소실되지 않도록 사용자 FK를
두지 않는다. 사용자 UUID를 지우거나 바꾸는 기능은 이번에 추가하지 않는다.

notify_reading_activity()의 기존 일반 활동 로직 앞에 한정된 보정 검사를 추가한다.
관리자 UUID, 동일 트랜잭션의 보호된 감사 행, 대상 사용자/Day, 변경 전후 날짜,
불변 One Verse JSON이 모두 일치할 때만 반환한다. 임의 GUC로 우회하지 않는다.
이는 관리자 본인 기록 수정 시에도 알림을 억제한다. 일반 One Verse 자동 완료 RPC,
친구/아멘 트리거 및 기존 연속 읽기 알림 보류 정책은 변경하지 않는다.

## 통계 의미

홈/달력/친구의 완료 판정은 여전히 completed_at이다. 보정 결과를 그대로 반영한다.
관리자 '오늘 One Verse'는 최초 감사 행 이전 completed_at으로 사용자 활동을
계산한다. 기존 미완료 → 관리자 완료는 새 활동으로 집계하지 않으며,
과거 완료를 오늘로 옮겨도 오늘 활동에 추가하지 않는다.
자연 발생한 오늘 완료를 과거로 보정해도 실제 활동 발생 근거는 유지한다.
마음새김 시간과 계산 조건은 변경하지 않는다.

이 방식은 현재 기록과 이번 감사 이력이 추적하는 보정에 한정된다.
이전 감사 없는 수동 SQL 보정이나 기록 삭제 후 동일 Day 재생성의 전체 활동 이력을
복원하는 시스템은 아니다. 기존 앱도 별도의 활동 원장을 수집하지 않는다.

## UI 및 검증

관리자에만 max-w-6xl을 적용하고 2열 상세 패널을 제거했다.
사용자 검색 → 기본 정보 → 기록 → 친구 → 아멘 → 알림 → 데이터 점검을
세로로 표시한다. 수정 모달은 확인/취소, 오류, 저장 중 중복 클릭 차단,
포커스 복귀 및 스크롤 잠금 정리를 제공한다.
성공 응답 후 해당 기록 상태와 요약/데이터 점검을 갱신한다.

`npm run test:admin-records`는 실제 PostgreSQL 엔진(PGlite)의 권한 거부,
NULL/anon, 날짜 유효성, 중복 요청, 오래된 수정, 감사 원자성, 개인 내용 보존,
관리자 본인 알림 억제, 일반 완료 알림 회귀, 오늘 활동 기준을 검증한다.
날짜 변환은 UTC/미국/한국 시간대에서 별도로 테스트한다.
이는 운영 API 로그인 테스트 또는 실제 다중 연결 동시성 부하 테스트가 아니다.
운영 DB 적용/인증 HTTP/실제 모바일 및 iOS PWA 조작 검증은 별도 필요하다.

기존 테이블의 ACL/TRUNCATE 문제는 이번 기능 범위 밖 후속 보안 점검으로 유지한다.
